Architecture Approaches

Three ways to build the document comparison solution. Click to select your preferred approach.

A

UiPath Coded App + Maestro Recommended

Build a UiPath Coded App (React-based, hosted on UiPath Platform) as the UI. Maestro orchestrates the full comparison pipeline. Human task sent back to same app for user confirmation.

Pros
  • Native UiPath ecosystem
  • Maestro human tasks built-in
  • No external hosting
  • Auth via UiPath Identity
Cons
  • Coded Apps = more dev work
  • Deployment via UiPath Platform
  • Limited to platform features
Stack: UiPath Coded App → Maestro Process → Document Understanding → LLM → Human Task → Coded App confirm
B

Custom Web App (React/Next.js) + UiPath SDK + Maestro

Standalone web app (React + TypeScript, builds on existing project setup). TypeScript SDK triggers Maestro. Full control over UI — rich diff viewer, scorecard, narrative — all custom rendered.

Pros
  • Full UI/UX control
  • Rich diff visualization
  • Leverages existing TS project
  • Can integrate any library
Cons
  • Need separate hosting
  • Build own auth layer
  • More infrastructure work
Stack: React frontend → Node/Express API → UiPath TS SDK → Maestro → webhook callback → frontend
C

Lightweight Trigger App + Action Center + Maestro

Minimal custom UI for document upload only. Maestro handles orchestration. UiPath Action Center handles human task confirmation UI. Least custom code, fastest to ship.

Pros
  • Fastest to build
  • Action Center = no UI work
  • Proven human task flow
Cons
  • Action Center UI = fixed/generic
  • Poor rich diff display
  • Split UX (two different apps)
Stack: Simple upload form → Maestro → DU + LLM → Action Center task → confirmation
My recommendation: Option A — stays fully in UiPath ecosystem, Maestro human tasks integrate natively with Coded Apps, no external hosting needed, and Coded Apps give enough flexibility for the scorecard + diff + summary UI.
